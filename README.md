📌 About This Project

This project demonstrates the implementation and testing of a basic network sniffer in a controlled Kali Linux laboratory environment.

The sniffer captures network packets and extracts useful information such as:

Source IP address

Destination IP address

Protocol

Packet length

Available packet payload

The project also includes controlled network testing with ICMP ping and DNS resolution using nslookup, followed by observation of the resulting traffic.

🎯 Project Objectives

The main objectives of Task 1 were to:

Understand the fundamentals of network packet capture.

Implement a basic packet sniffer using Python and Scapy.

Observe network traffic generated by the Kali Linux system.

Identify source and destination IP addresses.

Recognize network protocols.

Examine packet lengths and available payload data.

Perform basic packet analysis.

Understand the security implications of captured network traffic.

📊 Testing Performed

ICMP Testing

Network traffic was generated using:

ping -c 4 8.8.8.8

The supplied evidence shows successful ICMP responses with packet loss varying between test runs.

DNS Testing

DNS resolution was tested using:

nslookup example.com

The command returned DNS information for example.com, including IPv4 and IPv6 results.

📦 Packet Analysis

The captured traffic demonstrated packets involving the Kali VM and external destinations.

The sniffer output displayed information such as:

Source IP      → 10.0.0.5
Destination IP → External destination
Protocol       → TCP / ICMP
Packet Length  → Example: 54, 60, 83 bytes
Payload        → Available packet data when present

This demonstrates how packet-level information can be extracted and examined during network monitoring.

🧠 Key Security Lessons

This task provided practical understanding of:

How network packets travel between systems.

How source and destination addresses identify communication endpoints.

How different protocols generate different traffic.

How packet payloads may contain sensitive information.

Why captured network data must be handled securely.

Why network sniffing should only be performed on systems and networks where monitoring is authorized.

Why credentials should never be exposed in public repositories.

⚠️ Challenges & Troubleshooting

Network packet loss

The ICMP testing showed different packet-loss results across runs. This demonstrated that network response can vary during testing.

Packet interpretation

Some packet payload information appeared as binary or encoded data rather than readable text. This required understanding that packet contents are not always directly human-readable.

Verification approach

The environment was verified first, then recognizable traffic was generated using ping and nslookup. The resulting packets were examined to confirm that the sniffer was operating correctly.
